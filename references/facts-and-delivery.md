# 事实与文档交付

## 产品事实

从课程总纲和当前原稿找出涉及的功能，再按主题查询当前官方指南，不把整本手册搬进技能。

| 主题 | 优先查找 |
|---|---|
| 画布、节点、连接、版本 | 无限画布、基础节点、工作流、画布功能 |
| 图片与参考 | 图像生成器、标记、智能引用、角色三视图、故事板、九宫格 |
| 图片处理 | 人像调节、打光、全景、多角度、基础编辑、宫格切分 |
| 视频与后处理 | 视频生成器、模式、逐帧拉片、重拍、延展、编辑、声音 |
| 进阶制作 | 脚本节点、导演台、智能剪辑、资产 |
| 智能辅助 | Agent、Skill、Plugin／CLI、当前支持的接入方式 |
| 模型 | 图片、视频、音频模型清单；本次任务实际使用的模式与参数 |

- 名称存在不等于所有旧操作、入口和限制仍然正确。用资料中的具体描述核实；价格、权益、可用选项等再按当前可访问状态核对。
- 区分官方支持、某次实际结果、用户个人经验和计划演示。单次成功不能写成必然复现，“5秒视频”不等于“5秒生成完”。
- 没有证据时保留原有论述供核对，按确认责任标记具体文字：LibTV等外部确认用红色背景，黄白或内部待定用黄色背景，附简短原因和确认对象。不要把错误当待确认继续传播。
- 不通过付费生成去验证文案，除非本次已有相应授权。写好演示需求不等于做好了素材。

## 表格

大纲与脚本统一执行 [大纲与脚本格式标准](table-standard.md)：先大纲后脚本，大纲三列、脚本七列，前三列逐字对应；列序、真实合并和固定列宽都按该标准。不再使用旧六列或保留多余制作列的规则。

用户已确定稿件后的大纲、导图、音频同步，走 [对齐功能](alignment.md)。保护定稿口播，以当前确定稿为准；“先大纲后脚本”不授权反改定稿。默认只处理选定脚本文档，不连带写回独立大纲或父文档。

保护的是当前有效文字、图片、附件、制作说明、批注语境及用户确认的教学内容。格式整理时将旧列有效内容迁入合法列，而非删除其内容；只改口播时不顺手改无关内容和附表。

大纲“内容”用简洁清楚的项目符号；总纲若有“讲什么”列亦同。不同功能按实际任务与操作顺序讲，不强套“生成前／生成后”。

## 长稿协作与基线

- 用户要求逐节独立子任务时，每节用新的独立上下文处理；提供本节链接、相关技能、当前要求和必要衔接，不把整段历史交给每个子任务。主任务统一审查语气、课序、标色和素材保留。
- 明确每份文档的唯一写入者；并发限于不同文档。若从逐段修改切换为整张表局部替换，先结束旧写入过程并确认最后结果，再从线上最新版重建剩余改动。
- 首次读取另存不可变的 `original-baseline`；后续快照用 `pre-update`、`after`、`final` 等名字，不覆盖首次基线。前后对照、改动统计和资源核验都以真正首次版计算，不能把续写中间稿充当改前稿。
- 大量改动集中在同一张表时，可合并成一次目标主表的局部替换，按新标准重排列与合并，同时保留原文、资源和表外内容。若长表写入失败，先回读实际状态；按官方接口分步建立、合并、填入同一正式表格，全部核验通过后再移除旧表。不反复提交同样失败的整表请求，不以另建文档冒充完成。
- 正文保护不能只看行数：同时比较未授权改动的原块内容、表格列宽和合并，以及图片／附件的位置、显示尺寸、缩放和裁剪。精确裁剪图有疑问时下载前后文件比对。
- 产品的限制与案例选择分开，例如“这次选五段素材”不等于“产品最低必须五段”；未核实的免费、自动化范围和必然成功等承诺，不作为确定口播。

## 飞书写回

仅在用户要求改文档且授权范围明确时写回；分析、创建技能或给建议本身不触发线上改稿。

1. 使用飞书CLI及 `lark-doc` 技能；按其当前参考确认参数，`lark-cli whoami` 核实身份。
2. 读取最新总纲、本节唯一完整文档及相关评论；按当前主表整理有效大纲，需要追溯才读归档旧大纲，保存完整正文与引用信息；入口失效时先核对当前Wiki父子关系，不能继续使用已删除入口。用当前块标识和版本。
3. 以最小授权范围修改。局部口播优先局部替换，保留原素材；避免整篇覆盖。原稿与目标不是同一文档时，不把原稿评论别名当作目标评论写入。
4. 红色和黄色都使用原生文字背景，不能仅改字体颜色或只写“待确认”。待LibTV等外部确认标红，内部待定标黄；修改已确认表达不自动标色。
5. 写后重新读取，比较前三列内容组及顺序、列宽、真实合并、知识点、口播、结尾、媒体归属与高亮。媒体复制可能更换编号，需结合文件内容、尺寸、图注、缩放和裁剪核对；回读浅灰常为rgba(245,246,247,0.9)，不要把样式枚举与实际颜色字符串不同误判为失败。
6. 仅报告实际完成项；核验没有覆盖视频播放或功能实测时，不声称已经验证这些结果。没有用户授权不回复评论或向协作者发消息。

## 试听与资源

正文品牌保留 `LibTV`，送入音频朗读的内部文本才替换成“哩布 TV”。用户要求生成试听时用黄白音色，核对实际设置，不沿用旧默认音色；明确标注合成试听。

旧头像和旧版UI等参考资料不能改个名字冒充新素材。旧讲师试听删除与“暂无”是此前阶段的决定，不能覆盖用户后来授权生成的本人试听；以本节现场状态和最新授权为准。保留课堂案例的配乐、对白和音效，不擅自清理原版、备份或云盘文件。资源是否替换、谁提供、是否已完成分开记录；后期、配套画布与资料由LibTV提供，黄白主讲和拍摄。清单与批量配音见 [配套素材与试听](materials-and-preview.md)。
